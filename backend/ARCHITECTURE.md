# bid4 backend — architecture

Spring Boot 4.1 / Java 21 / PostgreSQL 17 / Redis 7 / MinIO. The HTTP contract is
already fixed by the frontend: every function in `frontend/src/lib/api/*` names
the endpoint it will call. This service implements that contract and nothing
wider.

## Runtime topology

`docker-compose.yml` at the repo root owns the whole stack.

| Service    | Purpose                                        | Published on   |
| ---------- | ---------------------------------------------- | -------------- |
| `postgres` | System of record                               | 127.0.0.1:5432 |
| `redis`    | Rate limiting, login throttling, short-lived state | 127.0.0.1:6379 |
| `minio`    | Object storage: imagery and identity documents | 127.0.0.1:9000 |
| `backend`  | This service (profile `app`)                   | 127.0.0.1:8080 |

Every published port binds to `127.0.0.1`, so the databases are reachable from
this machine and from the compose network and never from the LAN. The default
`docker compose up` starts infrastructure only; `--profile app` adds the API.

## Package layout

Package by feature, not by layer. A feature owns its entities, repository, service
and controller, so a change to causes touches one directory.

```
ro.bid4.backend
├─ common/       error handling, money, platform config, validation, paging
├─ security/     authentication, authorisation, rate limiting, headers
├─ identity/     users, sessions, delivery methods, payment methods
├─ cause/        causes, verification, documents, the operator queue
├─ catalog/      products, auctions, bids
├─ order/        orders, escrow, shipping, invoices, disputes
├─ storage/      MinIO gateway, presigned URLs, upload validation
└─ ops/          actuator wiring, health, audit log
```

Money is `long` bani everywhere, mirroring `lib/money.ts`. The fee split lives in
exactly one class and is the server-side twin of `computeFees`.

## Where each control sits

A request passes these in order, and each one can end it:

1. **Container limits** — Tomcat connection and header caps, multipart caps.
   Blunt DoS ceilings, set before any application code runs.
2. **Rate limit filter** — Redis token bucket keyed by IP for anonymous calls and
   by user id once authenticated. Buckets are per route class: reads are generous,
   writes are not, and `/auth/*` is the tightest.
3. **Security filter chain** — stateless, deny by default. Access tokens are
   short-lived JWTs verified by Spring Security's resource server (Nimbus), so
   there is no hand-rolled token parsing. Refresh tokens rotate and are stored
   only as SHA-256 hashes.
4. **Bean validation** — every request body is a record with constraints. Nothing
   binds straight onto an entity, so no request can set a field it does not own.
5. **Service rules** — authorisation on the object, not just the route: owning a
   valid token is never the same as owning the row.
6. **The schema** — CHECK constraints, partial unique indexes and foreign keys as
   the last backstop. See the probe list in `V1__core_identity.sql`.

### The specific attacks, and the specific answer

- **SQL injection** — JPA/Hibernate with bound parameters; no string-built SQL.
  Sorting and filtering map through allow-lists, never straight into a query.
- **XSS** — the API returns JSON with no HTML escaping burden, and the one
  free-text field a cause carries is run through the OWASP sanitizer on write.
  Uploads are restricted to `image/jpeg|png|webp` and `application/pdf` by an
  allow-list, enforced again by a CHECK constraint, so `text/html` cannot be
  stored and later served back. Objects are handed out as short-lived presigned
  URLs from a bucket with no anonymous policy.
- **Brute force** — two halves. Redis counts attempts per IP and per address in
  real time; `users.failed_login_count` / `locked_until` is the durable per-account
  half, so an attempt spread over many IPs still trips a lockout. Every attempt,
  successful or not, lands in `login_attempts`. Login answers in constant time
  whether or not the address exists.
- **DoS/DDoS** — Tomcat caps, per-route rate limits, request size limits, pagination
  ceilings, statement timeouts, and container CPU/memory limits. A single instance
  cannot absorb a real DDoS; the edge (CDN/WAF) has to, and this service is built
  to stay standing behind one.

## Data conventions

- `uuid` primary keys, generated by the database.
- `bigint` bani for money. Never `numeric`, never floating point.
- `timestamptz`, stored UTC.
- Enumerations are `varchar` + `CHECK`, mirroring the TypeScript unions exactly.
  A CHECK widens in a later migration without an exclusive lock.
- `created_at` / `updated_at` on every mutable table, with `updated_at` owned by a
  trigger rather than by whoever remembers.

## Decisions worth knowing

- **JWT via Spring Security's resource server**, not jjwt. Nimbus arrives with the
  starter and the verification path is the framework's, not ours.
- **Rate limiting is Bucket4j over Redis.** Bucket4j declares Lettuce 6.1.8 at
  `provided` scope while Boot supplies 7.5.2, a major version ahead, which is a
  binary-compatibility risk that no compiler catches. It was measured rather than
  assumed: `Bucket4jRedisCompatibilityTest` drives a real bucket against a real
  Redis and stays in the suite as the canary for the next upgrade. The library
  earns its place on `ConsumptionProbe` alone — remaining tokens and nanos-to-refill
  are what `X-RateLimit-Remaining` and `Retry-After` are built from, and that
  arithmetic is the part worth not hand-rolling.
- **Not the `com.giffing` Bucket4j Spring Boot starter**, which targets Boot 3.
  The library is used directly.
- **No Lettuce connection pool.** Lettuce is thread-safe and multiplexes every
  command over one connection; a pool only adds commons-pool2 and overhead.
- **No springdoc yet.** The published 2.x line targets Spring Framework 6; this is
  on 7. The API contract is documented by the frontend and by the Postman
  collection until a compatible release lands.
- **Both MinIO buckets are private.** Imagery and identity documents differ by
  presigned-URL lifetime and audit treatment, not by public access.
- **Jackson 3** (`tools.jackson.*`) ships with Boot 4. Annotations remain
  `com.fasterxml.jackson.annotation.*`.
